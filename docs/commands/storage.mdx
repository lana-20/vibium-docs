# vibium storage

Export or restore cookies and web storage.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium storage [-o file.json]
vibium storage restore <file.json>
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--output`, `-o` | `string` | Write the state to a file |

Global flags apply as well — see [Global flags](/docs/global-flags).

## Exporting

With no `-o`, the state goes to stdout:

```sh
$ vibium storage
{
  "cookies": [],
  "storage": {
    "localStorage": {
      "k": "v"
    },
    "origin": "https://lana-20.github.io",
    "sessionStorage": {}
  }
}
```

With `-o`, the same JSON is written to the file and the command reports the
path:

```sh
$ vibium storage -o /tmp/cap/state.json
State saved to /tmp/cap/state.json
```

## Reusing a login

This is the practical use — sign in once, then skip the login on later runs:

```sh
vibium go https://app.example.com/login
vibium fill "input[name=email]" "user@example.com"
vibium fill "input[name=password]" "secret"
vibium click "button[type=submit]"
vibium wait url "/dashboard"
vibium storage -o auth.json
```

```sh
vibium storage restore auth.json
vibium go https://app.example.com/dashboard
```

:::warning[`storage -o` ignores `--json` on this version]
The no-file form prints bare JSON; the `-o` form prints `State saved to …` as
plain text whether or not `--json` is given. Reported upstream as
[#451](https://github.com/VibiumDev/vibium/issues/451) and fixed after this
release.

Note also that an exported file contains **session cookies in clear text**.
Treat it as a credential: do not commit it.
:::
