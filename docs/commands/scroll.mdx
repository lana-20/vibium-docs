# vibium scroll

Scroll the page, or bring an element into view.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium scroll <up|down|left|right>
vibium scroll into-view <selector>
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--amount` | `int` | How far to scroll |
| `--selector` | `string` | Scroll within this element rather than the page |

Global flags apply as well — see [Global flags](/docs/global-flags).

## Scrolling the page

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium eval "window.scrollY"
0

$ vibium scroll down
Scrolled down by 3

$ vibium eval "window.scrollY"
360

$ vibium scroll down --amount 300
Scrolled down by 300

$ vibium eval "window.scrollY"
1055
```

The bare direction scrolls by a default step of 3 wheel notches; `--amount`
takes the count.

## `into-view`

Bring a specific element to the viewport, without caring how far that is:

```sh
$ vibium scroll into-view "#inner-frame"
Scrolled #inner-frame into view
```

## Scrolling does nothing inside a frame

:::danger[`scroll <direction>` silently fails in a frame context]
After [`vibium frame`](/docs/commands/frame), a directional scroll reports
success and moves nothing. The frame below holds a document 1833px tall in a
120px viewport, so it is plainly scrollable:

```sh
$ vibium eval "window.top === window.self"
false
$ vibium eval "document.documentElement.scrollHeight"
1833
$ vibium eval "window.innerHeight"
120

$ vibium eval "window.scrollY"
0
$ vibium scroll down --amount 300
Scrolled down by 300
$ vibium eval "window.scrollY"
0
```

`into-view` still works in the same context, and is the reliable choice inside
frames:

```sh
$ vibium scroll into-view "#advanced"
Scrolled #advanced into view
$ vibium eval "window.scrollY"
742
```

Directional scrolling is delivered as a wheel event at a point in the
**top-level** viewport, which is why it does not reach the frame's document.
:::

## JSON output

```sh
$ vibium scroll up --json
{"ok":true,"result":"Scrolled up by 3"}
```
