# vibium click

Click an element, identified by a ref from [`map`](/docs/commands/map) or
[`find`](/docs/commands/find), or by a CSS selector directly.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium click [url] [selector]
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--timeout` | `timeout` | Max time to wait, e.g. 5s or 5000 (bare number = milliseconds) (default 30s) |

Global flags apply as well — see [Global flags](/docs/global-flags).

## Clicking by ref

The usual flow is [`map`](/docs/commands/map) to discover, then `click` to act.
`click` echoes the element it resolved, which is worth reading: given a ref it
reports the *selector* it resolved to, not the ref you passed.

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium map | tail -4
@e10 [button type="button"] "Count"
@e11 [button type="button"] "Locked"
@e12 [button type="button"] "Reveal panel"
@e13 [a] "Next page"

$ vibium click @e10
Clicked element: #counter
```

## Confirming the click landed

`click` reports that it dispatched a click, not that the page did anything with
it. When the effect matters, assert on it:

```sh
$ vibium text "#status"
Ready

$ vibium click @e10
Clicked element: #counter

$ vibium text "#status"
Counted 1
```

:::warning[`click` acts, it does not set]
Every click is another click. The counter above increments again rather than
settling:

```sh
$ vibium click @e10
Clicked element: #counter

$ vibium text "#status"
Counted 2
```

The same applies to checkboxes, where a second click unchecks. Use
[`vibium check`](/docs/commands/check) and
[`vibium uncheck`](/docs/commands/uncheck) when you want a *state* rather than
an action — those are idempotent and safe to repeat.
:::

## Effects can be asynchronous

`click` returns as soon as the click is dispatched. If the page reacts later,
the very next command can still observe the old state. The fixture's "Reveal
panel" button updates its status a second after the click:

```sh
$ vibium click @e12
Clicked element: #reveal

$ vibium text "#status"
Ready

$ vibium wait text "Panel revealed"
Text "Panel revealed" found on page

$ vibium text "#status"
Panel revealed
```

The first read is not a bug — it is the page's real state at that moment. Follow
a click with [`vibium wait`](/docs/commands/wait) whenever the effect is not
synchronous.

## Elements that cannot be clicked

`click` waits for the element to become *actionable*, not merely present. A
disabled button is found immediately but never becomes clickable, so the command
waits out its timeout and **exits 1**:

```sh
$ vibium is enabled "#locked"
false

$ vibium click "#locked" --timeout 3s
Error: failed to click: timeout after 3s: enabled check failed — disabled attribute
$ echo $?
1
```

The error names the check that failed — `enabled check failed — disabled
attribute` — which distinguishes "the element is not there" from "the element is
there but not usable". A missing element reports differently:

```sh
$ vibium click ".nope" --timeout 2s
Error: failed to click: timeout after 2s: element not found
$ echo $?
1
```

:::note[Error wording differs from `find`]
[`find`](/docs/commands/find) reports the same missing element as
`element not found: .nope (timeout 2s)`. Both exit 1, but do not match on
message text if you script against both.
:::

## Clicking by CSS selector

A ref is not required; any CSS selector works, and is often clearer in a script
with no `map` step:

```sh
$ vibium click "a[href='#docs']"
Clicked element: a[href='#docs']

$ vibium url
https://lana-20.github.io/vibium-docs/fixtures/playground.html#docs
```

## Navigating first

Given two arguments, the first is a URL to navigate to before clicking, which
collapses a `go` and a `click` into one command:

```sh
$ vibium click "$PLAYGROUND" "a[href='#about']"
Clicked element: a[href='#about']

$ vibium url
https://lana-20.github.io/vibium-docs/fixtures/playground.html#about
```

## Clicks that navigate invalidate refs

Following a link discards the ref table. The ref you just clicked is not valid
on the page it took you to:

```sh
$ vibium map | tail -1
@e13 [a] "Next page"

$ vibium click @e13
Clicked element: #next-page

$ vibium title
Playground — second page

$ vibium click @e13 --timeout 3s
Error: failed to click: timeout after 3s: element not found
$ echo $?
1

$ vibium map
@e1 [a] "Back to the playground"
```

Re-map after any navigation before using a ref again.

## JSON output

```sh
$ vibium click "#terms" --json
{"ok":true,"result":"Clicked element: #terms"}
```
