# vibium pipe

Run as a child process speaking BiDi over stdin/stdout.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21** on macOS. Paths, ports and ids will differ on your machine.
:::

## Synopsis

```
vibium pipe
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--connect` | `string` | Connect to a remote BiDi endpoint |
| `--connect-header` | `string` | Header to send when connecting |

Global flags apply as well — see [Global flags](/docs/global-flags).

## What it does

`pipe` launches a browser and relays raw BiDi JSON between it and your process's
stdin/stdout. It is the transport a language client sits on top of, not
something to use interactively:

```sh
$ vibium pipe
[router] Launching browser for client 1...
[router] Browser launched for client 1 (BiDi session)
{"method":"browsingContext.contextCreated","params":{"children":null,"clientWindow":"557478037","context":"5E8F906E8B34748CA6C0E37C6F125DA2","originalOpener":null,"parent":null,"url":"about:blank","userContext":"default"},"type":"event"}
{"method":"vibium:lifecycle.ready","params":{"version":"26.8.21"}}
```

Events start arriving immediately, interleaved with `[router]` diagnostics on
the same stream — a client has to tolerate both.

`vibium:lifecycle.ready` is the signal that the session is usable.

:::warning[This command does not exit on its own]
It runs until interrupted, printing `Press Ctrl+C to stop...`. Do not call it
from a script that waits for completion — it will hang. Run it in the
background, or bound it explicitly (macOS has no `timeout(1)`).
:::
