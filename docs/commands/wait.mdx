# vibium wait

Block until the page reaches a condition — an element in some state, a URL, some
text, a finished load, or an arbitrary JavaScript expression.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium wait [selector]
vibium wait <fn|load|text|url> <value>
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--state` | `string` | State to wait for: attached, visible, hidden (default "attached") |
| `--timeout` | `timeout` | Max time to wait, e.g. 5s or 5000 (bare number = milliseconds) (default 30s) |

Global flags apply as well — see [Global flags](/docs/global-flags).

## When you need it

Most interaction commands auto-wait for their target, so `wait` is not needed
before a [`click`](/docs/commands/click). It is needed when you must observe a
*consequence* — the click returns as soon as it is dispatched, and the page may
react later.

## Waiting for an element

The bare form takes a selector and, by default, waits for it to be **attached**
to the DOM:

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium wait "#panel"
Element "#panel" reached state: attached
```

:::warning[`attached` is satisfied by a hidden element]
The command above returned immediately, and yet the panel is not on screen:

```sh
$ vibium is visible "#panel"
false
```

`attached` means *in the DOM*, which a hidden element is. Waiting for something
the user can actually see requires `--state visible` — otherwise a wait for a
lazily-shown element passes the instant its markup exists, long before it
appears.
:::

## `--state visible` and `--state hidden`

The fixture's "Reveal panel" button un-hides the panel a second after it is
clicked, which is exactly the case the bare form gets wrong:

```sh
$ vibium click "#reveal"
Clicked element: #reveal

$ vibium wait "#panel" --state visible
Element "#panel" reached state: visible

$ vibium is visible "#panel"
true
```

`--state hidden` is the inverse, and is the usual way to wait out a spinner. It
fails if the element stays visible:

```sh
$ vibium wait "#panel" --state hidden --timeout 2s
Error: timeout after 2s: element still visible
$ echo $?
1
```

## `vibium wait text`

Wait for text to appear anywhere on the page. Often the simplest way to confirm
an action landed, since it does not require knowing which element will hold the
result:

```sh
$ vibium wait text "Panel revealed"
Text "Panel revealed" found on page
```

## `vibium wait url`

Wait until the URL contains a substring — the standard way to confirm a
navigation finished:

```sh
$ vibium click "#next-page"
Clicked element: #next-page

$ vibium wait url "playground2"
URL matches pattern "playground2": https://lana-20.github.io/vibium-docs/fixtures/playground2.html
```

The match is a substring, not a pattern, despite the wording of the output.

## `vibium wait load`

Wait until the document has finished loading. The output names the `readyState`
it settled on:

```sh
$ vibium wait load
Page loaded (readyState: complete)
```

## `vibium wait fn`

Wait until a JavaScript expression returns truthy — the escape hatch when no
other form expresses the condition:

```sh
$ vibium wait fn "document.readyState === 'complete'"
Expression returned truthy: true

$ vibium click "#counter"
Clicked element: #counter

$ vibium wait fn "document.querySelector('#status').textContent === 'Counted 1'"
Expression returned truthy: true
```

## Timeouts

Every form exits **1** on timeout. The messages are not consistent with one
another, which matters if you are matching on them:

```sh
$ vibium wait ".nope" --timeout 2s
Error: timeout after 2s waiting for '.nope': element not found

$ vibium wait url "nowhere" --timeout 2s
Error: timeout after 2s waiting for URL matching 'nowhere'

$ vibium wait text "Nope" --timeout 2s
Error: timeout waiting for text "Nope" to appear

$ vibium wait fn "false" --timeout 2s
Error: timeout waiting for expression to return truthy: false
```

:::note[Only some messages name the duration]
The selector and URL forms report `timeout after 2s`; the text and expression
forms omit the duration entirely, even though `--timeout 2s` was honoured in
all four cases. Match on the exit code, not the message.
:::

## JSON output

```sh
$ vibium wait "#panel" --json
{"ok":true,"result":"Element \"#panel\" reached state: attached"}

$ vibium wait load --json
{"ok":true,"result":"Page loaded (readyState: complete)"}

$ vibium wait text "Ready" --json
{"ok":true,"result":"Text \"Ready\" found on page"}
```
