# vibium start

Launch the browser session.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium start [ws-url]
```

## Flags

This command takes no flags of its own. Global flags apply — see
[Global flags](/docs/global-flags).

## Starting

Every other command launches the browser on demand, so `start` is only needed
when you want the launch to happen at a predictable moment:

```sh
$ vibium start
Browser launched (chrome, headless: true)
$ echo $?
0
```

It is **idempotent** — a second call reports the existing session rather than
launching another:

```sh
$ vibium start
Browser already running
$ echo $?
0
```

## Connecting to a remote browser

Given a WebSocket URL, `start` connects instead of launching:

```sh
vibium start ws://remote-host:9515/session
```

:::note[The remote form ignores `--json` on this version]
`vibium start` with no URL emits an envelope under `--json`; the remote-connect
branch prints `Connected to …` as plain text either way. Reported upstream as
[#451](https://github.com/VibiumDev/vibium/issues/451) and fixed after this
release.
:::
