# vibium content

Replace the current page's HTML with markup you supply.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium content <html>
vibium content --stdin
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--stdin` | — | Read HTML from stdin |

Global flags apply as well — see [Global flags](/docs/global-flags).

## Replacing the page

The command reports the number of characters it set:

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium text "h1"
Playground

$ vibium content "<h1>Replaced</h1><p>New body</p>"
Page content set (32 chars)

$ vibium text "h1"
Replaced
```

This is the quickest way to get a known page under test without hosting a
fixture — useful for reproducing a bug against exact markup.

## The URL does not change, and the title is lost

:::warning[After `content`, the page's identity is misleading]
`content` replaces the document but not the address bar, and the replacement
discards `<head>`:

```sh
$ vibium url
https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium title

```

`url` still reports the page you navigated to, though none of its content
remains; `title` is now empty. Neither is a reliable signal about what the
browser is actually showing after a `content` call.

Scripts and styles from the original page are gone too — the fixture's counter
button stops working, because its handler went with the old document.
:::

## Reading from stdin

`--stdin` avoids shell quoting problems, and is the better choice for anything
with nested quotes or newlines:

```sh
$ echo "<button id=fromstdin>From stdin</button>" | vibium content --stdin
Page content set (41 chars)

$ vibium map
@e1 [button] "From stdin"
```

## Getting back

`content` does not affect history, so re-navigating restores the real page:

```sh
vibium go "$PLAYGROUND"
```

## When the new content has nothing interactive

[`map`](/docs/commands/map) says so plainly, and exits 0:

```sh
$ vibium content "<h1>Replaced</h1><p>New body</p>"
Page content set (32 chars)

$ vibium map
No interactive elements found
$ echo $?
0
```

## JSON output

```sh
$ vibium content "<p>j</p>" --json
{"ok":true,"result":"Page content set (8 chars)"}
```
