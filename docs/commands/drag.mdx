# vibium drag

Drag one element onto another.

## Synopsis

```
vibium drag <source> <target>
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--timeout` | `duration` | Max time to wait, e.g. `5s` or `5000` (a bare number is milliseconds; default 30s) |

Global flags apply as well — see [Global flags](/docs/global-flags).

## Dragging

The fixture's drop target rewrites itself when something lands on it, so the
effect is observable:

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium text "#drop-target"
Drop here

$ vibium drag "#drag-source" "#drop-target"
Dragged "#drag-source" to "#drop-target"

$ vibium text "#drop-target"
Dropped

$ vibium text "#status"
Drop received
```

`drag` performs a full pointer sequence — press on the source, move, release on
the target — so pages that implement HTML5 drag-and-drop respond to it. Pages
that implement dragging with their own pointer handlers generally do too.

As with [`click`](/docs/commands/click), the command reports that the gesture
was performed, not that the page accepted it. Assert on the consequence.
