# vibium mouse

Move and click the pointer by coordinate.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium mouse move <x> <y>
vibium mouse click [x] [y]
vibium mouse down
vibium mouse up
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--button` | `int` | 0 left, 1 middle, 2 right |

Global flags apply as well — see [Global flags](/docs/global-flags).

## Moving and clicking

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium mouse move 100 100
Mouse moved to (100, 100)

$ vibium mouse click
Clicked at current position
```

With coordinates, `click` moves and presses in one step:

```sh
$ vibium mouse click 50 50
Clicked at (50, 50)
```

## Coordinates are viewport-relative

They are not page coordinates, so scrolling changes what sits under a given
point. Check with [`vibium viewport`](/docs/commands/viewport) and remember that
`--full-page` screenshots are taller than the coordinate space.

Prefer [`vibium click`](/docs/commands/click) with a selector wherever possible:
it waits for the element to be actionable, whereas `mouse click` presses a
location whether or not anything is there — and reports success either way.

## Building a gesture

`down` and `up` allow a press-move-release sequence that
[`drag`](/docs/commands/drag) otherwise does for you:

```sh
vibium mouse move 100 100
vibium mouse down
vibium mouse move 200 200
vibium mouse up
```
