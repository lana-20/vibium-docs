# vibium daemon

Manage the background process that owns the browser.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium daemon start
vibium daemon status
vibium daemon stop
```

## Flags

This command takes no flags of its own. Global flags apply — see
[Global flags](/docs/global-flags).

## Why there is a daemon

Every command talks to a long-lived daemon over a unix socket, which is why
state persists between invocations — the browser, the page, the element
references and the cookies all outlive any single command.

## `status`

```sh
$ vibium daemon status
vibium daemon v26.8.21
status:   running
pid:      23998
uptime:   12m1s
socket:   /Users/lanabegunova/Library/Caches/vibium/vibium.sock
```

:::tip[`daemon status` is one of the few commands with a useful exit code]
It exits **1** when the daemon is down, so it works in a conditional — unlike
[`vibium is`](/docs/commands/is), which always exits 0:

```sh
$ vibium daemon status
Daemon is not running.
$ echo $?
1
```

```sh
vibium daemon status >/dev/null || vibium daemon start
```
:::

## `stop`

Stopping when nothing is running is not an error:

```sh
$ vibium daemon stop
Daemon is not running.
$ echo $?
0
```

Note the asymmetry with `status`, which exits 1 in the same situation.

[`vibium stop`](/docs/commands/stop) stops the daemon too, so you rarely need
`daemon stop` directly.

## `--json` returns JSON, but not the envelope

:::warning[`daemon status --json` has no `ok` key]
```sh
$ vibium daemon status --json
{"running":false}
```

Every other command's `--json` wraps its result as `{"ok":true,"result":…}`. This
one returns a bare object, so a consumer that parses first and reads `ok` second
gets a missing-key error rather than a clean "not JSON" signal. Verified still
present on current `main`.

`daemon start` and `daemon stop` ignore `--json` entirely and print plain text.
:::
