# vibium select

Choose an option in a `<select>` dropdown.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium select <selector> <value>
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--timeout` | `timeout` | Max time to wait (default 30s) |

Global flags apply as well — see [Global flags](/docs/global-flags).

## Selecting by value

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium value "#country"
us

$ vibium select "#country" "de"
Selected value "de" in #country

$ vibium value "#country"
de
```

## The visible label works too

The fixture's `de` option is labelled "Germany", and either identifier selects
it:

```sh
$ vibium select "#country" "Germany"
Selected value "Germany" in #country

$ vibium value "#country"
de
```

:::note[The message always says "value", whichever you passed]
`Selected value "Germany"` is echoing your argument, not reporting what was
set — the option's value is `de`, as the following
[`value`](/docs/commands/value) call shows. Read back with `value` if you need
to know what the form will actually submit.
:::

## No matching option

A value that matches neither an option value nor a label is a hard error, and
the selection is left untouched:

```sh
$ vibium select "#country" "nonsense"
Error: failed to select: selectOption: no <option> matches "nonsense"
$ echo $?
1

$ vibium value "#country"
de
```

## JSON output

```sh
$ vibium select "#country" "us" --json
{"ok":true,"result":"Selected value \"us\" in #country"}
```
