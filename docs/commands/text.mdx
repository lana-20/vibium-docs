# vibium text

Read text from the page, or from one element.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium text [url] [selector]
```

## Flags

`text` takes no flags of its own. Global flags apply — see
[Global flags](/docs/global-flags).

## Reading an element

A selector or a ref both work, and the ref is resolved through the same table
[`map`](/docs/commands/map) fills:

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium text "h1"
Playground

$ vibium text "#status"
Ready

$ vibium map | head -1
@e1 [a] "Home"

$ vibium text @e1
Home
```

## Reading the whole page

With no selector, `text` returns the page's text:

```sh
$ vibium text
Home Docs About
Playground

A fixed page for the examples in this reference.

Email
Country
United States
Germany
 Accept terms
 Sign In ×
Interactions
Count Locked Reveal panel
```

Layout is not preserved in any dependable way — inline elements run together
(`Sign In ×`), and whitespace comes from the markup rather than the rendering.
Match on substrings, not on exact shape.

## `text` reads hidden content

:::warning[This is not what the user can see]
`text` returns an element's text whether or not it is rendered. The fixture's
panel is hidden, and `text` reads it anyway:

```sh
$ vibium is visible "#panel-text"
false

$ vibium text "#panel-text"
Panel is open
```

That makes `text` the wrong tool for "has this appeared yet". Use
[`vibium is visible`](/docs/commands/is), or
[`vibium wait --state visible`](/docs/commands/wait).

It is also the opposite of [`map`](/docs/commands/map), which lists only
rendered elements. The two disagree by design.
:::

## Inputs have no text

A form field's content is its *value*, not its text, so `text` returns nothing
and still exits 0:

```sh
$ vibium text "#email"
$ echo $?
0
```

Use [`vibium value`](/docs/commands/value) for form fields.

## When the element is missing

Unlike a hidden or empty element, a missing one is an error:

```sh
$ vibium text ".nope"
Error: failed to get text: element not found
$ echo $?
1
```

## JSON output

```sh
$ vibium text "h1" --json
{"ok":true,"result":"Playground"}
```
