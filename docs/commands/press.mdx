# vibium press

Press a single key. Given a selector, `press` clicks that element to focus it
first; without one, it presses on whatever is already focused.

## Synopsis

```
vibium press <key> [selector]
```

The key comes **first**, which is the opposite order from most other commands.

## Flags

`press` takes no flags of its own. Global flags apply — see
[Global flags](/docs/global-flags).

## Pressing a key on an element

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium fill "#email" ""
Filled "" into #email

$ vibium press "a" "#email"
Pressed a

$ vibium value "#email"
a
```

## Submitting a form with Enter

```sh
$ vibium fill "#email" "a@b.com"
Filled "a@b.com" into #email

$ vibium press "Enter" "#email"
Pressed Enter

$ vibium text "#status"
Form submitted
```

:::warning[A form that fails validation will not submit, and `press` still reports success]
`press` reports that the key was delivered, not that the page acted on it. The
fixture's email field is `type="email"`, so an invalid value makes the browser
block submission — and the only difference in the output is the page state you
have to go and check yourself:

```sh
$ vibium fill "#email" "a"
Filled "a" into #email

$ vibium press "Enter" "#email"
Pressed Enter

$ vibium text "#status"
Ready
```

Same command, same success line, no submission. Assert on the consequence — a
[`text`](/docs/commands/text) read or
[`vibium wait text`](/docs/commands/wait) — rather than on `press` exiting 0.
:::

## The focus click moves the caret

With a selector, `press` clicks the element's **center** to focus it, which
places the caret at that point rather than at the end of any existing text. A
key pressed into a field that already has content can therefore land in the
middle of it:

```sh
$ vibium fill "#email" "abcdefghijklmnopqrstuvwxyz"
Filled "abcdefghijklmnopqrstuvwxyz" into #email

$ vibium press "Z" "#email"
Pressed Z

$ vibium value "#email"
abcdefghijklZmnopqrstuvwxyz
```

This is the same focus-click that affects [`vibium type`](/docs/commands/type),
where the consequences and their measurement are documented in full. The help
text does say `press` clicks to focus; what it does not say is that the caret
moves with the click.

## One Backspace empties a date, not one character of it

On an ordinary text input, `Backspace` deletes one character. On the five
segmented date and time types it clears the whole value:

```sh
$ vibium go 'data:text/html,<input id="x" type="text" value="abcdef"><input id="d" type="date" value="2020-01-02">'

$ vibium press "Backspace" "#x"
Pressed Backspace
$ vibium value "#x"
abcde

$ vibium press "Backspace" "#d"
Pressed Backspace
$ echo $?
0
$ vibium value "#d"

```

The date field is now empty. `Backspace` clears the **focused segment** — the
day, in a field the click landed on — and a segmented control with a missing
segment has no complete value to report, so the whole thing reads back as `""`.
The command has nothing to warn about: the key was delivered, and delivering it
is all `press` claims to do.

It applies to `date`, `time`, `month`, `week` and `datetime-local`, all of which
go from a seeded value to `""` on one press:

| type | seeded value | after one `Backspace` |
|---|---|---|
| `date` | `2020-01-02` | `""` |
| `time` | `10:30` | `""` |
| `month` | `2020-01` | `""` |
| `week` | `2020-W02` | `""` |
| `datetime-local` | `2020-01-02T10:30` | `""` |

This is not the focus click described above, and not something Vibium adds. It
is how the browser treats these controls, so
[`vibium focus`](/docs/commands/focus) followed by a selector-less `press` gives
the same empty field, and so does [`vibium keys`](/docs/commands/keys). Any tool
sending that key gets the same result.

:::warning[Firefox differs on `month` and `week`, and the difference confirms the mechanism]
Firefox does not implement `month` or `week`, and renders them as ordinary text
inputs. There, one `Backspace` deletes exactly one character — `2020-01` becomes
`2020-0` and `2020-W02` becomes `2020-W0` — while `date`, `time` and
`datetime-local` empty as they do on Chrome. Only the genuinely segmented
controls lose everything.
:::

Read the value back if a partial edit was the point:

```sh
$ vibium press "Backspace" "#d"
Pressed Backspace
$ [ -n "$(vibium value '#d')" ] || echo "the field is now empty"
the field is now empty
```

To clear one of these fields on purpose, [`vibium fill`](/docs/commands/fill)
with `""` says what it means and does not depend on which segment had focus.

## Pressing on the focused element

Omitting the selector presses on whatever currently has focus. There is no
click, so the caret stays where it was — this is the form to use when position
matters:

```sh
$ vibium focus "#email"
Focused element: #email

$ vibium press "Enter"
Pressed Enter
```

[`vibium keys`](/docs/commands/keys) works the same way and additionally handles
combinations:

```sh
$ vibium keys "Enter"
Pressed keys: Enter
```

## JSON output

```sh
$ vibium press "b" "#email" --json
{"ok":true,"result":"Pressed b"}
```
