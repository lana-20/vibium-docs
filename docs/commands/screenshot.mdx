# vibium screenshot

Capture the page as a PNG — the viewport by default, the whole scrollable page
with `--full-page`, or with every interactive element labelled with `--annotate`.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium screenshot [url]
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--output`, `-o` | `string` | Output file path (default "screenshot.png") |
| `--full-page` | — | Capture the full page instead of just the viewport |
| `--annotate` | — | Annotate interactive elements with numbered labels |

Global flags apply as well — see [Global flags](/docs/global-flags).

## Basic capture

With no `-o`, the file lands at `./screenshot.png`. The command prints the
absolute path it wrote, which is the reliable thing to parse:

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium screenshot -o shot.png
Screenshot saved to /tmp/shots/shot.png
```

The capture is the viewport, so its dimensions are the viewport's — check them
with [`vibium viewport`](/docs/commands/viewport) if a screenshot comes back an
unexpected size:

```sh
$ vibium viewport
{"width":756,"height":469,"devicePixelRatio":1}
```

That is exactly the size of `shot.png` above: **756 × 469**.

## Capturing the whole page

A plain capture stops at the fold. `--full-page` captures the entire scrollable
document — the fixture is about twice the viewport height:

```sh
$ vibium screenshot -o shot.png
Screenshot saved to /tmp/shots/shot.png

$ vibium screenshot -o full.png --full-page
Screenshot saved to /tmp/shots/full.png
```

| File | Flags | Dimensions |
| --- | --- | --- |
| `shot.png` | — | 756 × 469 |
| `full.png` | `--full-page` | 756 × 1052 |

The width never changes; only the height grows, to the full scroll height of the
document. On a long page the difference is dramatic — the same pair against this
reference's own [`find`](/docs/commands/find) page gives 756 × 469 and
756 × 5408.

## Annotating interactive elements

`--annotate` overlays a numbered badge on every interactive element. The numbers
line up with the refs from [`vibium map`](/docs/commands/map) — badge **6** is
`@e6` — which makes it the fastest way to see what a ref actually points at:

The two flags combine, which is usually what you want — badges below the fold
are only captured with `--full-page`:

```sh
$ vibium screenshot -o annotated-full.png --annotate --full-page
Screenshot saved to /tmp/shots/annotated-full.png
```

![The playground fixture captured full-page, with thirteen numbered red badges overlaying its links, inputs, select, checkbox and buttons](/img/annotate-example.png)

That is the real output of the command above. Compare it with the `map` listing
on the [map page](/docs/commands/map): thirteen elements, thirteen badges, same
order. Badge **11** is the disabled "Locked" button — `--annotate` labels it like
any other, since it numbers what `map` lists rather than what can be clicked.

:::note[Badges are drawn over the page, not beside it]
A badge sits on top of the element it labels, so it can obscure the start of a
short label — `@e4`'s badge covers the beginning of the email placeholder, and
`@e10`'s covers the start of "Count".
The annotated capture is for orientation; use a plain capture when you need to
read the page itself.
:::

## Navigating first

Given a URL argument, `screenshot` navigates before capturing:

```sh
$ vibium screenshot "$PLAYGROUND" -o nav.png
Screenshot saved to /tmp/shots/nav.png
```

## JSON output

`screenshot` honours the global `--json` flag. The path comes back inside the
envelope rather than on its own line:

```sh
$ vibium screenshot -o j.png --json
{"ok":true,"result":"Screenshot saved to /tmp/shots/j.png"}
```
