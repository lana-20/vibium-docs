# vibium is

Test an element's state. Four subcommands: `visible`, `enabled`, `checked` and
`actionable`.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

:::danger[Every `is` command exits 0, whatever the answer]
The answer is on **stdout**, not in the exit status. A shell conditional
therefore always takes the success branch:

```sh
$ vibium is visible "#panel"
false
$ echo $?
0

$ if vibium is visible "#panel" >/dev/null; then echo "taken"; else echo "not taken"; fi
taken
```

The panel is not visible, and the `if` ran anyway. Compare the output instead:

```sh
[ "$(vibium is visible '#panel')" = "true" ] && echo "visible"
```
:::

## Synopsis

```
vibium is <visible|enabled|checked> <selector>
vibium is actionable <selector>
```

## Flags

`is` takes no flags of its own. Global flags apply — see
[Global flags](/docs/global-flags).

## `visible`, `enabled`, `checked`

Each prints `true` or `false`:

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium is visible "h1"
true

$ vibium is visible "#panel"
false

$ vibium is enabled "#counter"
true

$ vibium is enabled "#locked"
false

$ vibium is checked "#terms"
false
```

`is checked` is the only correct way to read a checkbox — its
[`value`](/docs/commands/value) is `on` whether ticked or not.

:::warning[A missing element is reported as `false`, not as an error]
```sh
$ vibium is visible ".nope"
false
$ echo $?
0
```

"Not visible" and "does not exist" are the same answer. If the difference
matters, check existence first with [`find`](/docs/commands/find), which does
exit 1 when nothing matches.
:::

## `actionable`

`is actionable` runs the five checks an interaction command performs before
acting, and prints them as a human-readable list:

```sh
$ vibium is actionable "#counter"

Checking actionability for selector: #counter
✓ Visible: true
✓ Stable: true
✓ ReceivesEvents: true
✓ Enabled: true
✗ Editable: false
```

All five are always reported, whether or not they apply — a button is not
editable, so `✗ Editable` is expected here rather than a problem. It is the
check that matches your intended action that matters.

On the disabled button, the check that would block a
[`click`](/docs/commands/click) shows as failed:

```sh
$ vibium is actionable "#locked"

Checking actionability for selector: #locked
✓ Visible: true
✓ Stable: true
✓ ReceivesEvents: true
✗ Enabled: false
✗ Editable: false
```

This maps directly onto the errors the action commands produce —
`enabled check failed` from [`click`](/docs/commands/click), `editable check
failed` from [`fill`](/docs/commands/fill).

## JSON output

`visible`, `enabled` and `checked` honour `--json`, with the boolean as a
**string**:

```sh
$ vibium is visible "#panel" --json
{"ok":true,"result":"false"}

$ vibium is checked "#terms" --json
{"ok":true,"result":"false"}
```

:::warning[`is actionable` ignores `--json` on this version]
It prints the same human-readable checklist and exits 0:

```sh
$ vibium is actionable "#locked" --json

Checking actionability for selector: #locked
✓ Visible: true
✓ Stable: true
✓ ReceivesEvents: true
✗ Enabled: false
✗ Editable: false
```

There is no machine-readable form, and since the exit status is 0 however many
checks fail, a script has no channel to read the result from at all. Reported
upstream as [#451](https://github.com/VibiumDev/vibium/issues/451) and fixed
after this release. Until then, use the individual subcommands, which do emit
envelopes.
:::
