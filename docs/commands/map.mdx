# vibium map

List every interactive element on the page and assign each one a numbered
reference — `@e1`, `@e2`, and so on — that other commands accept in place of a
CSS selector.

:::tip[Verified against a live browser]
Every example on this page is real terminal output captured from **vibium
v26.8.21**, run against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed page served
from this repo, so the output cannot drift when someone else's markup changes.
Every example is reproducible against that URL exactly as shown.
:::

## Synopsis

```
vibium map
```

## Flags

| Flag | Argument | Description |
| --- | --- | --- |
| `--selector` | `string` | Scope to elements within this CSS selector |

Global flags apply as well — see [Global flags](/docs/global-flags).

## Description

`map` is the usual first step after navigating: it tells you what is on the page
and gives you a handle for each thing you might act on. It lists only
*interactive* elements — links, buttons, inputs, selects — not every node.

Each entry shows the ref, the tag with any type, and whatever best identifies
the element: its text if it has any, otherwise a distinguishing attribute.

```sh
$ PLAYGROUND=https://lana-20.github.io/vibium-docs/fixtures/playground.html
$ vibium go "$PLAYGROUND"
Navigated to https://lana-20.github.io/vibium-docs/fixtures/playground.html

$ vibium map
@e1 [a] "Home"
@e2 [a] "Docs"
@e3 [a] "About"
@e4 [input type="email"] placeholder="you@example.com"
@e5 [select] "United StatesGermany"
@e6 [input type="checkbox"] name="terms"
@e7 [input type="search"] placeholder="Search docs"
@e8 [button type="submit"] "Sign In"
@e9 [button type="button"] title="Close dialog"
@e10 [button type="button"] "Count"
@e11 [button type="button"] "Locked"
@e12 [button type="button"] "Reveal panel"
@e13 [a] "Next page"
```

Note `@e11`: `map` lists the disabled "Locked" button even though nothing can
click it. The listing describes what is *on* the page, not what is actionable —
use [`vibium is enabled`](/docs/commands/is) to tell the difference.

**Hidden elements are the opposite case**: they are left out entirely. The
fixture's panel contains a button that does not appear above, because the panel
is `hidden` — it shows up only once something reveals it:

```sh
$ vibium click "#reveal"
Clicked element: #reveal

$ vibium wait "#panel" --state visible
Element "#panel" reached state: visible

$ vibium map | tail -2
@e13 [button type="button"] "Panel action"
@e14 [a] "Next page"
```

So `map` lists what is *rendered*, whether or not it can be acted on: disabled
but visible is in, present but hidden is out. That is also what makes
[`vibium diff map`](/docs/commands/diff) useful for spotting what an action
revealed.

Note `@e5`: a `<select>` is labelled with its options' text run together, so a
two-option dropdown reads as `"United StatesGermany"`. That is the label, not
the value — use [`vibium value`](/docs/commands/value) to read what is selected.

## Scoping with `--selector`

On a large page, `--selector` restricts the map to one subtree:

```sh
$ vibium map --selector "nav"
@e1 [a] "Home"
@e2 [a] "Docs"
@e3 [a] "About"

$ vibium map --selector "#interactions"
@e1 [button type="button"] "Count"
@e2 [button type="button"] "Locked"
@e3 [button type="button"] "Reveal panel"
@e4 [a] "Next page"
```

:::warning[Scoped refs are renumbered, not filtered]
A scoped map always numbers from `@e1`. In the output above, `@e1` means the
"Home" link when scoped to `nav` but the "Count" button when scoped to
`#interactions` — and on the unscoped map, that same button is `@e10`.

Refs are only meaningful relative to the map that produced them. Never carry a
ref across two different `map` invocations.
:::

## Refs are rebound by `find`, too

[`vibium find`](/docs/commands/find) assigns refs from the same table, so a
`find` after a `map` overwrites the numbering:

```sh
$ vibium map | head -3
@e1 [a] "Home"
@e2 [a] "Docs"
@e3 [a] "About"

$ vibium text @e1
Home

$ vibium find "button"
@e1 [button type="submit"] "Sign In"

$ vibium text @e1
Sign In
```

`@e1` now refers to the button. Re-map before using a ref if anything has
happened in between.

Refs also do not survive a navigation — see
[`vibium back`](/docs/commands/back).

## JSON output

`map` honours the global `--json` flag. The refs come back as one newline-joined
string in `result`, not as an array:

```sh
$ vibium map --json
{"ok":true,"result":"@e1 [a] \"Home\"\n@e2 [a] \"Docs\"\n@e3 [a] \"About\"\n@e4 [input type=\"email\"] placeholder=\"you@example.com\"\n@e5 [select] \"United StatesGermany\"\n@e6 [input type=\"checkbox\"] name=\"terms\"\n@e7 [input type=\"search\"] placeholder=\"Search docs\"\n@e8 [button type=\"submit\"] \"Sign In\"\n@e9 [button type=\"button\"] title=\"Close dialog\"\n@e10 [button type=\"button\"] \"Count\"\n@e11 [button type=\"button\"] \"Locked\"\n@e12 [button type=\"button\"] \"Reveal panel\"\n@e13 [a] \"Next page\""}
```
