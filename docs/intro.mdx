# Vibium CLI reference

[Vibium](https://github.com/VibiumDev/vibium) is a browser automation CLI for AI
agents and humans. It exposes **67 commands**, and this site documents all of
them, including their 41 subcommands.

:::note[Why this site exists]
The official documentation covers 16 of the 67 commands. This is an independent
reference that covers the rest. It is community-maintained and not affiliated
with the Vibium project; where behavior here disagrees with upstream, upstream
wins.
:::

## How the examples were produced

Every example on every page is real terminal output, captured from **vibium
v26.8.21**. Nothing on this site is transcribed from `--help`. Most pages run
against this site's own
[playground fixture](pathname:///vibium-docs/fixtures/playground.html) — a fixed
page served from this repo, so the output cannot drift when someone else's
markup changes — and those examples are reproducible against that URL exactly as
shown. Where output is machine-specific, the page says so: paths, ports and
process ids differ per machine, and a captured home directory is shown as `~`.

## Install

```sh
npm install -g vibium
```

Or run any command without installing:

```sh
npx -y vibium go https://example.com
```

## A first session

```sh
vibium go https://example.com     # navigate
vibium map                        # list interactive elements as @eN refs
vibium click @e1                  # act on one
vibium text                       # read the page back
```

All commands share a single browser and daemon, so state persists between
invocations — there is no session to thread through by hand.

## Behaviors worth knowing before you script anything

Verifying all 67 commands turned up a number of cases where a command reports
success and does not do what you would expect. They are documented in full on
the relevant pages; these are the ones that cost the most time.

**Every one of them is still live in v26.8.21**, the current npm release. Four
have been fixed since, but only on `main`, so the fix has not reached anyone
installing the CLI today — and one of those fixes is partial. Upstream status was
re-measured against `main` on 2026-09-12.

| Behavior | Page | Upstream |
| --- | --- | --- |
| `type` does not append — it inserts wherever the focus-click lands, mid-value | [type](/docs/commands/type) | fixed on `main` ([#488](https://github.com/VibiumDev/vibium/issues/488)) for text-like fields, but still broken on **seven input types** where the caret cannot be placed — `number`, `email` and the five segmented date types ([#529](https://github.com/VibiumDev/vibium/issues/529), open; [#507](https://github.com/VibiumDev/vibium/issues/507) covers `number` alone) |
| `type` reports success on elements it cannot type into at all | [type](/docs/commands/type) | partly fixed on `main`: a `<button>` now errors, a `<span>` still reports a successful type. Unreported |
| `fill` reports success for a value the field cannot hold — the field is left empty, or on a substitute the browser picked | [fill](/docs/commands/fill) | open ([#530](https://github.com/VibiumDev/vibium/issues/530)) |
| Every `is` subcommand exits 0 by default, so `if vibium is visible …` always runs — `--fail` fixes it | [is](/docs/commands/is) | not a defect: `--fail` was added for this in [#206](https://github.com/VibiumDev/vibium/issues/206), before v26.8.21 |
| A click that opens a dialog times out after 60s and exits 1 — the click worked | [dialog](/docs/commands/dialog) | unchanged. Unreported |
| `upload` accepts a path that does not exist and attaches a zero-byte file | [upload](/docs/commands/upload) | fixed on `main` ([#480](https://github.com/VibiumDev/vibium/issues/480)) |
| `frame` switches context permanently, and `go` navigates the frame rather than leaving it | [frame](/docs/commands/frame) | fixed on `main` ([#510](https://github.com/VibiumDev/vibium/issues/510), closed by [#527](https://github.com/VibiumDev/vibium/pull/527)) |
| `scroll <direction>` does nothing inside a frame, while reporting success | [scroll](/docs/commands/scroll) | fixed on `main` ([#511](https://github.com/VibiumDev/vibium/issues/511), closed by [#528](https://github.com/VibiumDev/vibium/pull/528)) |
| A failed `go` leaves you on the engine's error page, which maps and reads cleanly | [go](/docs/commands/go) | unchanged, and arguably correct. Unreported |
| `value` on a checkbox is `on` whether ticked or not | [value](/docs/commands/value) | unchanged. Unreported |
| `a11y-tree` omits every accessible name that comes from text content | [a11y-tree](/docs/commands/a11y-tree) | open ([#512](https://github.com/VibiumDev/vibium/issues/512)) |

Most share a shape: the command reports what it **dispatched**, not what the page
did with it. Assert on the consequence — a [`text`](/docs/commands/text) read or
a [`wait`](/docs/commands/wait) — rather than on the exit code.

## Contributing

`scripts/gen_pages.py` reads the installed binary and rebuilds the command
reference index, the global flags page and the command list in the README. After
a vibium release:

```sh
python3 scripts/gen_pages.py
```

The per-command pages are written by hand, because captured output is not
something help text can supply. They are listed in that script's `CURATED` set,
which it never overwrites; a command added upstream joins the list once its
output has actually been captured.
